EXP 1 — PASSWORD STRENGTH TESTING USING PYTHON
================================================================================

PROGRAM (p1.py):
----------------
import re

def password_strength_checker(password):
    if(len(password)<8):
        return "Weak:password should contain atleast 8 length"
    if not any(ch.isdigit() for ch in password):
        return "Weak:password should contain atleast 1 digit"
    if not any(ch.islower() for ch in password):
        return "Weak:password should contain atleast 1 lower"
    if not any(ch.isupper() for ch in password):
        return "Weak:password should contain atleast 1 upper"
    if not re.search(r'[!@#$%^&*(){}<>,.|]',password):
        return "Medium:Not special character"
    return "Strong password"

def run():
    while True:
        input1=input("Enter your password or exit to exit");
        if(input1.lower()=="exit"):
            return "exited"
            break
        print(password_strength_checker(input1));

run();

RUN COMMAND:
------------
python p1.py

SAMPLE INPUT/OUTPUT:
--------------------
Input: abc123       → Weak:password should contain atleast 8 length
Input: Abcdef12     → Medium:Not special character
Input: Abc@1234     → Strong password

------------------------------
# Navigate to: DVWA → Vulnerabilities → Brute Force

Username: admin  Password: admin     → FAIL
Username: admin  Password: 123456    → FAIL
Username: admin  Password: password  → SUCCESS
# No lockout = Brute Force Vulnerability

PART B — SESSION ID ANALYSIS:
-------------------------------
Right-click → Inspect → Storage → Cookies → note PHPSESSID (visible, not encrypted)

PART C — SESSION HIJACKING:
-----------------------------
1. Login → copy PHPSESSID from DevTools → Storage → Cookies
2. Open Private Window (Ctrl+Shift+P) — do NOT login
3. DevTools → Storage → Cookies → paste PHPSESSID → F5
4. Result: Logged in as admin WITHOUT password → Session Hijacking

PART D — SESSION FIXATION:
----------------------------
1. Note PHPSESSID before login
2. Login → check PHPSESSID after login
   LOW security : PHPSESSID SAME before/after → Session Fixation
   HIGH security: PHPSESSID CHANGES after login → Secure

PART E — IMPROPER LOGOUT:
---------------------------
1. Login → copy PHPSESSID → Logout
2. Open Private Window → paste old PHPSESSID → http://127.0.0.1/dvwa/index.php
3. Result (LOW): Still logged in — logout did NOT destroy session

OBSERVATIONS TABLE:
--------------------
Test Case               | Result
------------------------|--------------------------------

LOG DIRECTORY:
---------------
cd /var/log && ls
# Key files: dpkg.log, apache2/, journal/, wtmp, btmp

KEY COMMANDS:
--------------
last                                           # Successful logins
journalctl | grep "Failed"                     # Failed SSH attempts
journalctl | grep ssh                          # SSH activity
journalctl | grep -i error                     # Error detection
sudo less /var/log/apache2/access.log
grep "404" /var/log/apache2/access.log         # Detect probing
sudo journalctl -f                             # Real-time monitoring

SIMULATE & ANALYZE FAILED SSH LOGINS:
---------------------------------------
sudo apt install openssh-server -y
sudo service ssh start

# Generate failed attempts:
ssh fakeuser@localhost    # enter wrong password multiple times

# Analyze:
journalctl | grep "Failed password"
journalctl | grep "Failed password" | awk '{print $11}'
journalctl | grep "Failed password" | awk '{print $11}' | sort | uniq -c | sort -nr
journalctl --since "10 minutes ago"
sudo lastb

-----------------
